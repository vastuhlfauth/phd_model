# EMP 2019 (Enquête mobilité des personnes), public tables

- **Source:** SDES, EMP 2019 ("Enquête mobilité des personnes"), national household travel survey; public microdata release ("Tables Définitives"), version 4 (data), version 3 (most tables' dictionary codes). `config/sources.yaml` source id `emp2019`.
- **Vintage(s):** fieldwork 2018-2019; public release December 2021, last updated November 2024.
- **Local path:** `data/raw/emp2019/emp2019-data.zip` (CSVs), `emp2019-dictionary.xlsx` (variable list per table), `emp2019-categories.pdf` (categorical code labels), `emp2019-documentation.pdf`.
- **CRS:** none (tabular microdata only; no coordinates).
- **Keys and joins:** `IDENT_IND` (person) links `K_DEPLOC` (trips), `TCM_IND_KISH_public` (the Kish-selected respondent's demographics) and `K_INDIVIDU_public` (that respondent's individual weight and commute-equipment answers). `IDENT_MEN` (household) links to `Q_MENAGE_public` (household weight and vehicle fleet). Only the Kish-selected respondent of each household has a travel diary (`K_DEPLOC`); the five tables below share that respondent universe except `TCM_MEN`/`Q_MENAGE` (household level) and `TCM_IND_public` (every household member, used for linkage tables, not demographics).
- **Encoding:** the five CSVs are Windows-1252 (French accents); DuckDB's CSV reader only accepts UTF-8/Latin-1, so `mobgrid.budget.emp2019.extract_tables` re-encodes each file to UTF-8 once, under `data/interim/emp2019/csv/`.
- **Delimiter:** `K_DEPLOC` (zip member `5. k_deploc_public_V4.csv`) is comma-separated with `"`-quoted fields; `TCM_IND_public`, `TCM_IND_KISH_public`, `K_INDIVIDU_public` and `Q_MENAGE_public` are semicolon-separated, unquoted.
- **Nulls:** the literal string `NA`, except a few categorical codes (e.g. `SITUA` for a child too young to answer) which are an empty string instead.
- **Used by:** step 11 (`mobgrid.budget.emp`), section 9.9's re-estimation.

## Quirks

- `mtp`'s categorical codes are stored as floats (e.g. `3.2`), so code `5.10` ("autres transports urbains et régionaux sans précision") is numerically identical to `5.1` ("autobus urbain"): DuckDB (and any other float-based reader) cannot distinguish the two. `mobgrid.budget.emp2019` groups them together, which is harmless for its vehicle mapping (both are "urban_bus").
- `K_DEPLOC` has no leg-by-leg breakdown (no separate walk-to-stop/wait/ride durations); only the trip's overall `mtp`, `DUREE` and `MDISTTOT_fin` are given. `MTEMPSMAP` (walking time within the trip) and `MTPSATTENT` (PT waiting time) are the trip's own declared terminal-leg minutes: since the 27 October 2026 decision (section 9.9), `mobgrid.budget.trip_legs.build_trip_legs`'s default `terminal_legs='declared'` uses them (replacing the car/carpool/PT/bike terminal-leg defaults of sections 9.4-9.7, falling back to those defaults where a value is missing); `terminal_legs='defaults'` keeps the former, defaults-only model for the F8 robustness sweep.
- `Q_MENAGE_public` and `TCM_IND_public` were checked present and are read by `mobgrid.budget.emp2019.extract_tables`/`register_views`, but none of their columns are used by step 11's formulas (no house/apartment split or vehicle-fleet data is needed by section 9.9's re-estimation steps 1-3 and 5).
